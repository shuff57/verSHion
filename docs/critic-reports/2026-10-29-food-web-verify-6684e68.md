## New defects (ranked)

1. **MED (new, introduced by this commit) — a route's arrival run and another route's departure run merge inside one
   inter-row gap.** `k` is a single global index over all long links, so a *departure* run at lane `k_d` and an
   *arrival* run at lane `k_a` that occupy the **same** gap collide when `(k_d + k_a) * step ≈ clear − 2*drop`
   (Medium: 25 px, `step` = 6 → `k_d + k_a = 4`). Repro (Medium, levels on, 7 names, 7 links, 4 levels, 4 long
   links): `P0 -> P1 / P1 -> P2 / P2 -> P3 / X0 -> P2 / X1 -> P2 / X2 -> P3 / P1 -> P3`. Measured from the emitted SVG:
   `X1->P2` arrival run at **y = 150.00, x[274.3, 394.8]** and `P1->P3` departure run at **y = 151.00,
   x[271.2, 418.8]** — **dy = 1.00 px < stroke 1.5 px**, **x-overlap 120.5 px**. They draw as one ~2.5 px double
   line under the secondary row; the lanes and endpoints are still correct, so no false edge is added, but you cannot
   tell which of the two lanes leaves `P1`. This is a **regression**: the pre-fix commit renders the same web with the
   arrival at y = 144 and the departure at y = 172 (**28 px apart**, no merge) — the two-omni fix's fixed per-link y
   offsets (py−8, qy+11) never collided across a gap; the stagger does. At Small/Large the same class fires at a
   different `k`-sum (Small `step` = 4.8, 2*drop−clear = 15.6, so `k_sum = 3` gives 1.2 px; Large `step` = 8.4).
   The fix needs the run height keyed per-gap (subtract only lanes whose run is in *that* gap, or reserve two
   independent stagers for departures and arrivals).
2. **LOW (new framing; not a regression) — with many long links the runs pack into one gap and merge into a solid
   band.** Every run height is distinct, but the spacing shrinks as `36/(n+1)`: visible gap **1.77 px at n=10**,
   **0.75 px at n=15**, **0.21 px at n=20**, **−0.12 px (strokes overlap) at n=25** (Medium; Small n=20 gap 0.06,
   Large n=20 gap 0.50). n=25 long links is reachable with **11 names** (`5 producers × 5 secondaries`, `cross_web(5,5)`);
   n=15 with 11 names (`cross_partial`, 15 of 25 cross links). At n≈25 I measured **48 near-collisions** (dy < stroke
   and x-overlap on every adjacent pair) and the render is two solid staircase bands. All-cross webs add no false
   edges (every relation exists), but a partial-cross web at n≈15 can again be mis-traced. This is *not worse* than
   the pre-fix single bus (which was one line at every n), but the fix does not scale: the "own run height" guarantee
   holds only while `36/(n+1) > stroke`, i.e. n ≲ 22 at Medium.
3. **LOW (carried, unchanged) — the mixed-arrow second line is still a paraphrase of its first line.**
   "Line 1 mixes -> and <-; use one direction on a line." / "Nothing is drawn until every line uses one direction."
   True and non-verbatim, so it is not the prior duplicate-cap defect, but it adds little. Not worse than round 1.
