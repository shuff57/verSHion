## Blockers (new class)

### B1. A student-data hold is lifted by the next clean version while the matching version stays readable (kept-version read)  -- HIGH

- Where: `src/pool/circlesend.ts` commit batch, the `DELETE FROM circle_holds ... source = 'privacy' ... AND NOT PRIVACY_SQL` and `privacy_near` statements (about lines 703-719); the read side is `src/pool/circles.ts` `getBank(..., version)` (about 1107-1170), which gates only on the bank's CURRENT hold state (`requireReadable`).
- Class: the hold is a property of the bank, but the confirmed student data is a property of a VERSION. D16 keeps the last 20 versions in full and `GET .../versions/:n` serves any of them. Lifting the hold when the new head is clean makes every kept earlier version readable, including the one that matched.
- Repro (a1.test.ts, ran): admin confirms text T as student data (purge of a public item). Ann (author) sends v2 containing T: `200 held:true`; member Eli `GET /banks/:bid` -> 404 and `GET .../versions/2` -> 404 (hold works). Ann sends v3 without T: `200 held:false`, hold row deleted, the `privacy_text_match` flag stays unresolved. Eli `GET .../versions/2` -> **200** with the body `["A clean question...", "Jenny Smith in period 3 scored 42 ... median?"]`. History shows v2 `kept:true`. Prune is also skipped while held, so it stays for up to 20 later versions. Members can read it and make a device copy.
- Impact: any author (or an editor, then the author) can push confirmed student data to every circle member with two sends (dirty, then clean), and the admin alert/flag no longer stops exposure (the bank is visible again before anyone reviews). It also undoes the "never a refusal, hold instead" design: the hold is the only protection and it is one send away from off. Rollback is covered (it re-scans), the version GET is not.
- Fix direction: do not lift a privacy hold while any kept (current/previous) version of the bank still matches; or mark matching versions unreadable (per-version `withheld` flag, checked in `getBank(version)`, `rollback`, blob route and `originsForRead`) until an admin releases; or prune/blank matched versions' `full_key` on lift. At least have the lift statement require the flag to be resolved.

## Variants / limits to document

1. **Origin laundering by omitting the qid** (a3.test.ts, ran). Recorded origins follow the qid only (`carried` map, circlesend.ts ~line 480). An editor who re-sends an honest author's declared-origin question WITHOUT `published.qid` (same text) gets a new qid: `200 added:1 removed:1` (no `confirm` needed, below half), the head's `origins` becomes `[]` (credit to the public author gone), and the author's `PATCH license: circle-only` then succeeds (it was `license_incompatible` before). Phase A's sender could already omit an origin; the new part is a THIRD party (an editor) stripping another author's declaration. Suggest: also carry an origin when the new question's key-free match hash equals a head question's with an origin, or flag "origin dropped" in the history line.
2. **`merged_from` attests nothing.** The token binds [exp 30 min, account, bank, base, head] with HMAC (own HKDF purpose, constant-time compare, JSON parsed only after the MAC, strict shape). Checked: other user's token, forged exp with the real MAC, demoted/removed holder, other bank: all `422 merge_token_invalid` or 403/404 (a2.test.ts). But the client picks any `base < head` and gets a token without having merged anything, and a token can be reused for any number of sends at that head until it moves or expires. The history label is only the client's claim. Document it as informational.
3. **Mail-budget starvation.** The circle `privacy_text_match` notice shares the `privacy_match` channel (5 mails/hour) with the public pool's notice (`alertBudgeted`). An author who toggles dirty/clean sends (each new hold writes a flag and mails; 100 sends/day) can use up the hour's budget so public re-publish alerts stay flag-only. Give circle notices their own channel.
4. **Rollback under-reserves memory relative to a send.** A send reserves `max(bytes*15, values*96*2)`; rollback reserves `size*15` only, then `JSON.parse`s and key-scans the body. A body with up to 200,000 values (the scan limit) in a small file reserves 38 MB at send but about 12 MB at rollback for ~800 KB. One heavy slot per isolate limits it to one at a time; low severity, but the "parity with publish" claim in the README is not exact. Reuse `scanJson(bodyBytes).values` in `rollbackOnce`.
5. **Shared heavy slot (queue 4) between public publishes and circle sends/rollbacks.** By design and unchanged in kind from publishes, but any 5 concurrent circle members' accounts can now fill it and 503 public publishes. Account-lock and daily caps (100 sends, 20 rollbacks) bound a single account only.
6. **Editor can put the bank on hold (griefing).** Only with text that matches a confirmed block, so it needs the student data; but the hold hides the bank from every member but its author and mails an admin. Limit; the admin release path exists.
7. **Rollback quota.** A rollback charges a full copy against `circle_bytes`; a circle near the cap cannot roll back (413) until something is removed. Availability only.
8. **Public author's name / item id in `origins` is read live** for items that were later taken down (only `anonymized` is checked, not moderation state). Minor.
9. `history` and `merge` are metered only by the general rate limiter (history counts as a read there; merge as a write), not by `item_reads` as a version GET is. Cost measured by the author is bounded (131 rows at caps).

## Nitpicks

- `verifyMergeToken` is called before the body is parsed (cheap), good; but the 422 message is identical for expiry, wrong user and wrong head, which is right for secrecy and hard for support: log the reason code in the audit-free metrics.
- `history` returns `oldest_kept` via a second query on every page; could be skipped for `before` > first page.
- `rollbackOnce` reads two R2 indexes before it takes the heavy slot; fine, but the order differs from `sendVersion` (slot first).
- README says rollback "publish-sized work"; see variant 4 for the one place it is not.
