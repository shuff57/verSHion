## MED
1. A single low-percentile reading gets no label in the key and the note offers no fix: the most common use, not a crowded state. Repro: default table, Reading = "Value at a percentile", pct 5, Medium, key: dashed L to 48.3, no text on either guide; note "no room for a label beside it", no step. Unlabelled: P1-P7 Medium, P1-P9 Large, P1-P5 Small (default table); Large up to P11 raw, P12 unequal table. 5 data sets x P1-P99 x 3 sizes, one reading, no Mark: 119 of 1,485 keys unlabelled, only 32 of those notes offer a fix, at Small 0 of 29. Values near the first boundary: 30 of 246 value readings unlabelled. Builder's account covers only reading + quartiles and the very first boundary; P5 and P10 are ordinary textbook questions. With reading + quartiles: 469 of 1,485 keys unlabelled (379 offer a fix); quartiles alone 0 of 144. Fix: label positions outside the cramped corner (side label right of the curve point, foot label below the x-axis, or a short leader); never print the note with no working step; single-reading sweep over every percentile in the tests.
2. Printed answers do not follow normal rounding and the IQR contradicts printed Q1 and Q3. num() formats the binary float: exact .5 goes to the even digit and decimal ties like 8.85 (stored 8.8499...) go down. Table `10, 20, 5` decimals 0: "Q1 about 12" (exact 12.5); flat table P33 decimals 1: "8.8" (exact 8.85); `1.25, 1.5, 3 / ...` median at 2 dp: "1.62" (exact 1.625). 63 of 1,584 percentile readings at 0 dp (4.0%) and 54 of 1,872 at 1 dp (2.9%) print one unit low. IQR is the rounded unrounded Q3-Q1: default table at decimals 0 prints Q1 about 62, Q3 about 81, IQR about 18 but a student gets 19 (same in 13 other cases). Test printed_readings_match_the_recomputation uses the same num() and locks it in. Fix: round the exact value half-up (as photosynthesis round 2 exact rounding did); compute the IQR from the printed Q1 and Q3, or print both and say which.
3. Stated limits are detected only when class width > gap, so the advice draws a wrong ogive for width-2 integer classes. Repro `0-1, 4 / 2-3, 7 / 4-5, 2 / 6-7, 1`: figure says "Add an empty class between them, for example "1, 2, 0""; following it three times draws boundaries 0,1,2,...,7 with three empty classes (flat steps); correct boundaries -0.5, 1.5, 3.5, 5.5, 7.5. Cause: `&& sorted.iter().all(|r| r.2 - r.1 > g)`; mutant M26 (condition deleted) survives. Fix: equal gaps are stated limits when width >= gap; add this table to tests.
4. Common table formats refused and the fix example is unrelated to the line: "Not a class" always says `for example "40, 50, 3"`. Refused: `40 - 49, 3` (spaced hyphen), `40 to 50, 3` (the figure's own wording), `40—50` (em dash), a `Total, 50` footer, two-column `midpoint, f`. Typing the example back destroys the data: `40 - 49 / 50 - 59 / 60 - 69` ends as one class `40, 50, 9` after five steps; `40 to 50 / 50 to 60` ends as `40, 50, 6`. The advice test counts any final drawing as success. Fix: parse "a - b", "a to b", em dashes; recognise a Total row ("delete line n"); build the example from the line's own numbers.
5. Nothing to read or plot against: no vertical or fine gridlines (class ticks every 10, horizontal grid lines every 10); key gives answers to 0.1 ("about 68.3") with no accepted range; plot-it-yourself copy asks students to plot 3, 10, 22, 37, 46 on gridlines 10 apart. Same class as photosynthesis critic 1 MED 1. Fix: fine grid (minor lines per class and y-step), Print greys darker than 66%, print an accepted range or tie default decimals to the grid resolution.
