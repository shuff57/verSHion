## BLOCKER 1 (pre-existing, also in df9c7c2): Chi-square, counts that print as 0 still run a test on "0 observations"

- Files:
  - `src/figures/biology/chisquarefit.rs:98` and `:107`: `fit` sums and divides the RAW f64 counts.
  - `:173`: the zero-observation refusal tests `*v == 0.0` on the raw values.
  - `:211-226`: `own_decimals`/`beyond_six` print the cells at six decimals.
  - `:155-166`: the new round-10 warning.
- Repro A: `{"obs":"0.0000004, 0.0000004","ratio":"1, 1"}` → `P/chi_tiny7dec_M.png` (`P/cmp_chi_a.png` lower pair: identical in
  df9c7c2). The page prints:
  - Observed `0.000000`, `0.000000`, Total `0.000000`
  - "Expected from the ratio 1 : 1 out of 0.000000 observations"
  - Expected `4.00e−7` twice, beside an Expected total of `0.000000`
  - χ² = 0.00, df = 1, p = 1.00, "do not reject the hypothesis: the counts are consistent with the ratio"

  The Expected cells contradict the Expected total and the givens. A test is run on zero printed observations, which round 6 made
  a refusal. The new editor note says: "Counts are used to six decimals, so “0.0000004”, “0.0000004” are rounded." That is false:
  the Expected cells show the unrounded 4e-7 was used.
- Repro B (no note at all): `{"obs":"1e-14, 1e-14","ratio":"1, 1"}` → `P/chi_1e-14_M.png`. The page shows Observed 0, 0, Total 0,
  "out of 0 observations", Expected `1.00e−14` twice, Expected total 0 and p = 1.00 "do not reject". `beyond_six` (`:221-225`)
  compares `|round(x) − x|` with `max(x·4e-16, 1e-7)` where x = v·1e6 = 1e-8, so a count below about 1e-13 is never reported.
  `0.00000000000001, 5` likewise prints 0 with no note. The round-10 warning misses the very case its "to 0 if small" wording
  came from.
- Expected behaviour: the fit should use the counts as printed (six decimals), or refuse whenever every printed count is 0, and the
  note should fire for any nonzero count that prints as 0.
