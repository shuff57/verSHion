## What is being built (components and what each builder owns)
- **server/share-core (Rust -> wasm, share-core builder).** The gate every publish passes through, running inside the Worker. `publish_prepare` / `validate_for_publish` check a teacher's bank/test and produce two forms: the full form (author keeps it, with answer keys) and the keyless "served" form (students/other teachers see it: answer keys stripped, choices shuffled/ordered per rules, labels stripped, text normalised). Its main job is the KEY-HINT GATE: refuse or ask for acknowledgement when a careless teacher left the answer in the visible text (e.g. "Answer: B" in a stem, a key list "1 C 2 B 3 D" in a bank description, a starred/bold correct choice, cloze/GIFT/LaTeX markers, word-bank order, True/False tallies). High-risk hints are never ackable; low-risk ones the author can acknowledge. It also computes the content hashes (keyed HMAC with POOL_HASH_KEY) and sketches the backend uses for duplicate/provenance matching, and hosts argon2id for passwords. Hard constraints: no wasm traps, no silent caps (a cap must refuse, never skip), CPU <= 5 s and memory <= 64 MB on 4 MB payloads, honest teachers rarely refused (<=2% acks, 0 hard on honest corpora). Spec: server/share-core/README.md.
- **server/worker (TypeScript Cloudflare Worker + D1 + R2, backend builder).** The pool service: publish/republish (with the own-work attestation), browse/preview, import (private copy with attribution + licence), licence and provenance engine (who published first, licence-at-serve, chains, "ghost" records of purged items, stock-question rule, authorship by order), reports (wrong answer, student data, copyright, key leak), takedown lifecycle (author notice, 30-day counter-notice, strikes, put-back, repeat-infringer flag), account deletion/erasure, data export (GET /me/export), admin approval of every teacher, rate limits and caps that fail closed. Spec: server/worker/README.md (Round 17-23 sections).
- **server/auth.** Generic email+password auth package (sessions, admin approval, rate limits), to be published open source later.
- **server/web/legal.** Static draft legal pages for Cloudflare Pages.
- **Rust client (src/share/*, store.rs, formats.rs).** Data layer done; UI not started (see Remaining work).

Convergence rule (mine): a critic finding is a BLOCKER only if it is a NEW CLASS: new hint channel/syntax family, honest-teacher hard refusal with no workable path (incl. false scan_budget), wrong freeze exposing the key by position, wasm trap, fail-open cap (a cap that silently skips a check), CPU > 5 s min-of-runs on 4 MB, or on the backend: new launder channel, wrongly refused/held honest teacher, data loss/resurrection, key reachable by a non-author, false credit/first. Language/spelling variants and exotic markers are non-blockers (documented limits). Exit: one clean critic pair each for share-core and backend (no new-class blocker), then rerun backend on the final share-core pkg.

### Merge (client, follow-up to slice 2)

"Merge into this bank..." sits beside "Add as a new bank..." on an update. It is a three-way merge like version control and only ever starts when the person presses it. Code: `src/share/merge.rs` (pure: `build_plan`, `apply_merge`), glue in `browse.rs` (`begin_merge`, `set_merge_choice`, `apply_merge`, `cancel_merge`), review screen in `browse_ui.rs`. No model change; nothing outside `src/share/` was edited.
- BASE: `ImportedRecord.base` in `share-imported.json`: for each imported question its local id, the pool's question id, a fingerprint, and a snapshot (text, kind with key, points, topics, explanation, picture hash, keyless flag) as imported or last merged. At most 500 questions / 1.5 MB per record, else no base is kept. OURS = the bank question with the stored local id. THEIRS = the version the update screen already loaded. Matching theirs to base is by the pool's question id (fingerprint when the pool gave none); a question the pool re-ids appears as removed plus new.
- Review categories: unchanged; changed in the pool only (take, default); changed by you only (keep); CONFLICT, both changed (keep mine / use the pool's / keep both; no default, Apply stays disabled until each is decided); new in the pool (add, default); removed from the pool (keep, default, or remove); deleted by you (stays deleted, and is still remembered as deleted by the next merge); licence changed (old and new shown; the bank's credit line changes only on Apply). Changed questions list the fields that differ (text, choices, answer key, explanation, points, topics, picture) as when imported / yours now / the pool's.
- Apply: fetches the pool's version again with `POST /items/:id/import` (that is how pictures are obtained), checks it is the version and content that was reviewed, writes a restore point, applies to a copy of the bank, replaces the bank once, advances the base to the pool's version, the record's version and clears the badge. Any failure before that (offline, signed out, 404, limits, a changed version, the restore point not writable) leaves everything as it was and returns to the review with the reason and the decisions kept.
- Restore point: `backups/banks-before-merge-<date>.json` in the app's data folder (`store::with_backend`, next to the automatic backups): a complete copy of all banks from just before. To go back, close verSHion and copy it over `banks.json`. The app has no in-app restore for it.
- Keys: a question imported without its key that the teacher re-keyed counts as changed by you even if only the key differs. If the pool changes only the wording, the wording is taken and the local key kept; if the pool changed the choices too, "use the pool's" is not offered (keep mine, or keep both). A final guard refuses any apply that would replace a typed key with the placeholder. "Keep both" adds the pool's version as a second question with a topic "From the pool: author, version N".
- Not merged: questions added by the teacher or copied from another bank (counted on the review as "not linked"), deleted ones, and a record with no base (imported before this, or too big): those can only be updated as a new bank, and the screen says why. Exporting a bank and importing it back, or copying a question to another bank, gives new local ids, so the link to the pool is lost for those copies; the review shows them only as "not linked to the pool".
- Declining a pool change (keep mine) still advances the base to the pool's version, as in git, so it is not offered again.
- Not run: a visual check of the review screen.
